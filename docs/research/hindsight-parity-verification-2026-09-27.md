**Hindsight parity verification — 27 September 2026**

The review confirms gaps in graph candidate retrieval, model-based reranking, automatic handling of changing knowledge, Khipu-owned consolidation, optional synthesis, and evaluation coverage. It also narrows several earlier claims. These are implementation findings, not measured claims that Hindsight is more accurate in Khipu's workflows.

**The three Khipu recall paths.**

| Path | Actual implementation | Required coverage for any enhancement |
|---|---|---|
| Explicit search | `khipu_search` calls `embed.hybrid_search`; omitted mode defaults to hybrid, but legacy `semantic=true` selects semantic. Stale snapshot fallback is available where a local snapshot exists. | Existing mode semantics, literal identifiers, confidence, filters, ranking, graph candidates, response compatibility. |
| Local prompt recall | Claude Code/Codex call `prior_work_for_prompt` without `budget_ms`; it uses local SQLite snapshot first, with a hub fallback. This is separate retrieval logic. | Snapshot export/schema, refresh, ranking, source metadata, ID/revision dedup, fallback, rendering. Local search has a 1.2-second cap. |
| Bounded hub recall | `khipu_status(prompt)` supplies `budget_ms`, selecting concurrent hub lexical/cosine work, default 600 ms, clamped 100–5000 ms. | Deadline/partial-result behavior, current-truth policy, quality, metadata, confidence, and compatibility of `prior_work`, `prior_work_text`, and `prior_work_meta`. |

**Explicit Aegis dependency notice.**

The existing `status(prompt)` path can receive improved Khipu results without an Aegis source change if its current schema and budgets remain intact. Full feature parity has these additional dependencies:

- Initial/fallback recall sends `semantic=true` by default without `mode`; enhanced hybrid retrieval requires an explicit adapter/config opt-in. Silently redefining the existing semantic mode is not the plan. [Client search](https://github.com/mrkinglollipop/aegis/blob/42dde0418822ead6a0c9fcf7f75629fdf8e1c467/crates/codegen/xai-grok-memory/src/khipu_client.rs#L434-L446).
- Aegis falls back to search when prior work is empty, missing, or an ordinary status error. A calibrated no-match result needs a supported-empty versus unsupported/error distinction; otherwise a fallback can negate abstention. [Fallback](https://github.com/mrkinglollipop/aegis/blob/42dde0418822ead6a0c9fcf7f75629fdf8e1c467/crates/codegen/xai-grok-memory/src/khipu.rs#L332-L378).
- Native result types consume fixed fields and ignore new evidence/validity/revision metadata. Rich provenance or revision-aware prompt dedup therefore needs parser/renderer work. Existing dedup uses IDs across the previous three turns. Keep stable IDs; do not disguise revisions as new source IDs. [DTO parsing](https://github.com/mrkinglollipop/aegis/blob/42dde0418822ead6a0c9fcf7f75629fdf8e1c467/crates/codegen/xai-grok-memory/src/khipu_client.rs#L583-L687), [dedup and renderer](https://github.com/mrkinglollipop/aegis/blob/42dde0418822ead6a0c9fcf7f75629fdf8e1c467/crates/codegen/xai-grok-shell/src/session/memory/khipu_recall.rs#L420-L615).
- A native source-record fetch or reflect experience would require an explicit consumer route. The Khipu backend's file `get` rejects `khipu://` records; generic MCP tool availability in the installed app was not established in this review. [Get boundary](https://github.com/mrkinglollipop/aegis/blob/42dde0418822ead6a0c9fcf7f75629fdf8e1c467/crates/codegen/xai-grok-memory/src/khipu.rs#L520-L557).

Retain Aegis's cache-stable system prefix, max-six initial results/default 2400-character slot, and max-three/600-character per-turn slot. Per-turn timeout defaults to two seconds. No Aegis code, config, tools, UI, or ledger changes are authorized by this plan.
