**Hindsight and Khipu — comparative research, 27 September 2026**

Hindsight is a direct competitor with additional retrieval and consolidation mechanisms worth evaluating. Khipu already implements much of the shared-memory foundation and has useful coding-workflow semantics of its own. The strongest opportunity is to improve evidence, changing facts, and retrieval within Khipu. This research does not establish that replacing Khipu with Hindsight would improve real outcomes.

This is a research recommendation, not an approved implementation scope. No application code, configuration, deployed service, or memory database was changed. Neither product's quality benchmark was executed in this investigation.

The subsequent [implementation verification](hindsight-parity-verification-2026-09-27.md) corrects and qualifies this initial comparison. In particular, persistent exact quotations were not established for Hindsight's consolidated observations, Khipu has event timestamps and a working manual supersession CLI, and Khipu's three recall implementations require separate acceptance. Use the [proposed scope](../plans/2026-09-27-memory-reasoning-scope.md) and [thin plan](../plans/2026-09-27-memory-reasoning-plan.md) for next steps.

**Recommended improvement order.** These are proposed priorities, not scheduled work or performance promises.

1. **Extend the evaluator first.** Keep current Khipu as a frozen control. Add cases for an approved plan, a reversed decision, an expired configuration, a deferred commitment, an existing artifact, indirect relationships, and a query with no relevant answer. Measure useful evidence, stale-answer rate, abstention, latency, and tokens as well as hit@k. Keep private golden data outside the public repository. The deliverable is a repeatable local gate, not a new dashboard.

2. **Make current truth traceable.** Build on the decision registry. Record source spans, speaker/source type, observed time, effective time, supersession, and derivation. Detect possible conflicts, but retain competing claims when authority or scope is unclear. A newer assistant paraphrase must not override an explicit user decision. Example: “use library A” on Monday and “replace A with B” on Thursday should yield B as current, while preserving the reason A was previously selected.

3. **Test graph/time retrieval and a small reranker as independent additions.** Use existing Khipu graph relationships to contribute candidates, then rank those candidates against the query. Keep the ability to retrieve exact commands and identifiers. Measure each addition separately so a costly component must earn its place. Preserve the existing fast prompt path; it currently has a 1.2-second ceiling and compact output. [Prompt budgets](https://github.com/mrkinglollipop/Khipu/blob/9d7d7e09ef63d760ce2fd526b7ed4c1785b6c209/packages/cli/khipu/recall_prompt.py#L41-L53).

4. **Evolve existing topic pages into evidence-backed project briefs.** Khipu should own the refresh contract even where a legacy producer remains temporarily. Refresh affected sections after evidence changes; show source references, revision, and stale state. Give a new session the current approved direction, unresolved obligations, and recent outcomes. Do not let generated summaries become self-confirming sources or silently replace the original evidence.

5. **Add optional reflection after evidence is dependable.** A proposed synthesis operation could answer “why did we abandon this approach?” or “which failure has repeated across sessions?” Return cited evidence and unresolved disagreement. Keep it outside automatic prompt recall, with explicit limits on work and output. LLM-driven consolidation and reflection add model work even when ordinary retrieval is inexpensive. [Operation configuration](https://github.com/vectorize-io/hindsight/blob/ccfe85b4851957ac2adf88b4a9ddf9668b2882f1/skills/hindsight-docs/references/developer/configuration.md).

Team namespaces are a separate, conditional product priority. If multiple people or organizations become a target, enforce authorization throughout episodes, vectors, graph traversal, derived pages, and exports. A shared database alone does not safely implement shared team memory.

**How much to trust the performance claims.** The paper reports 83.6% LongMemEval accuracy with a 20B model versus 39% for its same-backbone full-context baseline, and 91.4% with a larger backbone. The current vendor dashboard advertises 94.6% on LongMemEvalS. These are different reported configurations and publications; this investigation did not reproduce either. They support taking Hindsight seriously, not declaring it better than Khipu on coding work. [Paper](https://arxiv.org/abs/2512.12818), [current dashboard](https://benchmarks.hindsight.vectorize.io/).

Conversational question-answering scores do not establish that a coding agent obeys an approval, checks a repository's current state, closes the correct commitment, or distinguishes a planned action from an observed result. The README attributes reproduction to research collaborators; that is different from a neutral third-party head-to-head against Khipu. Model selection, preprocessing, retrieval budgets, and total write/refresh/read costs must be recorded in any comparison.

GitHub also provides useful failure scenarios for our design. Reports about quota exhaustion stranding consolidation ([#2973](https://github.com/vectorize-io/hindsight/issues/2973)), retired facts reappearing as current ([#3475](https://github.com/vectorize-io/hindsight/issues/3475)), and invalid LLM output causing destructive consolidation ([#3876](https://github.com/vectorize-io/hindsight/issues/3876)) are all **closed/completed**, confirmed through fresh GitHub REST records. They are historical reports, not verified current defects. They justify testing retry recovery, supersession, and atomic writes in any comparable Khipu feature. Fixed-version inclusion and reproduction were not checked here.

**The first comparison worth running.** Use the same synthetic session histories in an isolated Khipu control and an isolated self-hosted Hindsight instance. Include corrections, paraphrases, explicit quotations, temporal changes, commitments, artifacts, irrelevant queries, and authorized versus unauthorized scope boundaries. Test both the full capture-to-answer workflow and retrieval alone; otherwise differences in extraction can be mistaken for differences in search. Freeze commits, models, inputs, and budgets. Use the same answer model where practical and disclose unavoidable differences. Record ingestion/refresh cost separately from query cost, plus p50/p95 latency and timeout/miss rates. Do not send real private captures to hosted evaluation services.

The preferred strategy is incremental improvement inside Khipu. Using Hindsight as an optional experimental backend is a reasonable comparison candidate. Replacing the engine is a larger migration with no measured benefit established here, and would still need to preserve Khipu's commitments, deliverables, provenance, capture behavior, and desktop experience.
